# 로컬 모델 파인튜닝 검토

작성: 2026-10-12

NPC 대화에 쓰는 모델을 공개 모델(Ollama Mistral)이나 API(Gemini) 대신 로컬 모델을 파인튜닝해서 쓰는 방안을 검토한 내용입니다.

## 결론

진행할 만합니다. 다만 바로 파인튜닝하지 않고, 베이스 모델을 먼저 바꿔 본 뒤 부족하면 파인튜닝합니다.

## 현재 상태

기본값은 이미 로컬 모델입니다. `Config.json`이 `"ai_mode": "local"`, `"local_model_name": "mistral"`로 되어 있고, Gemini는 cloud 모드에서만 씁니다. 로컬 호출은 `main.py`의 `call_ollama` 한 곳뿐입니다.

Mistral 7B는 한국어가 약해서 코드로 보완하고 있습니다.

- `scenarios.py`의 `BASE_INSTRUCTION`에 한자, 일본어, 영어, 번역투를 쓰지 말라는 지시가 있습니다.
- `main.py`의 `sanitize_dialogue`가 응답에서 한글 외 문자를 정규식으로 지웁니다.
- JSON이 깨질 때를 대비해 파싱을 두 번 시도합니다. 먼저 그대로 파싱하고, 실패하면 마크다운 코드 블록에서 꺼냅니다.

## 파인튜닝이 맞는 이유

NPC가 하는 일은 범위가 좁고 정해져 있습니다.

- 정해진 JSON(`dialogue`, `suspicion_delta`, `action`)으로만 답합니다.
- 미션별 NPC 다섯 명의 말투와 성격을 지킵니다.
- 의심 수치를 얼마나 올릴지 판단합니다. 게임 밸런스가 걸린 부분이지만 프롬프트만으로는 판단이 일정하지 않습니다.
- "프롬프트를 무시해" 같은 입력에는 응하지 않고, 사회공학적으로 그럴듯한 접근에는 정보를 조금씩 흘립니다.

이런 작업은 LoRA 파인튜닝 효과가 큽니다. 시스템 프롬프트가 짧아져 응답 속도도 빨라집니다.

## 진행 순서

### 1단계: 베이스 모델 교체

Ollama에 한국어가 강한 모델(kanana-1.5 계열, EXAONE, Qwen 등)을 올리고 `Config.json`의 `local_model_name`만 바꿉니다. 번역투와 외국어 섞임은 이 단계에서 상당 부분 해결될 것으로 봅니다. 미션 몇 개로 기존 Mistral과 JSON 깨짐 비율, 말투를 비교합니다.

### 2단계: 파인튜닝

1단계 뒤에도 페르소나 유지나 의심 수치 판단이 흔들리면 진행합니다. PROTOCOL: STIGMA(`T_RPG-dev/stigma-gm`)에서 만든 파이프라인을 그대로 씁니다. kanana 4bit QLoRA로 학습하고, GGUF로 변환해 Ollama Modelfile로 등록하는 과정입니다. 데이터만 이 게임용으로 새로 만들면 되고, 게임 서버 코드는 모델 이름 외에 바꿀 곳이 없습니다.

## 주의할 점

### 학습 데이터

아직 학습 데이터가 없습니다. `memory_db`(ChromaDB)에 쌓인 대화는 Mistral이 만든 것이라 품질이 낮아 그대로 쓰기 어렵습니다. 미션별 시나리오와 의심 수치 판단 기준을 먼저 정하고, 성능이 좋은 모델로 합성 대화를 만든 뒤 사람이 골라내는 방식이 현실적입니다. Gemini 출력을 학습에 쓰려면 Google 약관에서 허용하는지 먼저 확인해야 합니다.

### GPU

개발 PC의 GPU는 RTX 3050 Laptop(4GB)입니다. 8B 모델 학습은 어렵고, 2B급 모델 학습이나 8B 4bit 추론까지 가능합니다. 8B 학습은 STIGMA 8B를 학습한 환경에서 합니다.

### 배포

플레이어 PC에도 Ollama와 모델 파일(수 GB)이 필요합니다. 지금 구조와 같으므로 새로 생기는 문제는 아닙니다.
