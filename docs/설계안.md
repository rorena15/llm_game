## 1. 게임 한 줄 요약

가짜 회사 PC 앞에 앉은 해커가 **이메일·웹·메신저 대화로 단서를 모으고, 수사보드에서 추론을 엮어, 대상의 비밀번호를 맞히는** 한국어 사회공학 추리 게임. NPC는 로컬 AI가 연기하고, 판정은 게임 엔진이 한다.

차별점: 한국어 직장 말투(하게체 부장, 해요체 대리)를 살린 NPC, OSINT 추리와 대화의 결합, 메타 프롬프트 해킹은 막히고 인물에 맞는 설득만 통하는 구조, 오프라인 무료.

## 2. 게임 루프

1. 타이틀 → 미션 선택 (앞 미션을 깨면 다음이 열림) → 의뢰 메일·브리핑
2. 가짜 데스크톱에서 단서 수집
   - **이메일**, **브라우저**(미션별 가짜 웹사이트), **메신저**(AI NPC)
   - 단서를 누르면 수사보드에 단서 카드가 생긴다
3. **수사보드**에서 단서 카드끼리 이어 **추론 카드**를 만든다 (§6)
4. **서버**에 비밀번호 입력 → 성공하면 기밀 문서 열람, 미션 클리어
5. 결과 화면 (등급), 다음 의뢰 메일
6. 마지막 미션을 깨면 엔딩 (§9)

실패 조건: 의심도 100 (NPC가 보안팀에 신고, 접속 차단).

## 5. NPC 엔진

### 5.1 원칙

- **모델은 분류하고 연기만 한다. 수치와 공개 여부는 엔진이 정한다.** 작은 모델에게 밸런스를 맡기면 흔들리고, 엔진 표로 두면 조정과 테스트가 쉽다.
- **모델이 모르는 것은 누출할 수 없다.** 아직 공개가 허락되지 않은 정보의 값은 프롬프트에 넣지 않는다.

### 5.2 사실(fact)과 공개 등급

| 등급 | 뜻 | 프롬프트 |
|---|---|---|
| `free` | 누구에게나 말함 (이름, 부서, 강아지 자랑) | 값까지 넣음 |
| `guarded` | 조건을 채우면 말함 (딸 생일, 대표 골프 스코어) | **이름표만** 넣음 ("딸 생일"). 값은 엔진이 허락한 턴에만 |
| `secret` | 대화로는 절대 나오지 않음 (비밀번호 원문) | 넣지 않음 |

### 5.3 상태

세션마다 엔진이 가진 값:
- `suspicion` 0~100: 100이면 실패, 80 이상이면 경고 연출
- `rapport` 0~100: 친밀도. `guarded` 공개 조건에 쓰임
- `revealed`: 공개한 사실 id
- `history`: 이 세션의 대화 전체 (미션이 끝나면 버림)

### 5.4 한 턴의 흐름

**① 판정 호출** (짧은 JSON, 약 30토큰)
```json
{ "tactic": "flatter", "topic": "bday", "meta": false, "fit": 2, "leverage": "pw_rule" }
```
- `tactic`: `flatter`(아부) · `rush`(재촉) · `empathy`(공감) · `pretext`(사칭·핑계) · `ask`(직접 요구) · `chat`(잡담) · `hostile`(무례·협박)
- `topic`: 플레이어가 캐묻는 사실 id (프롬프트에 준 이름표 목록에서 고름) 또는 `null`
- `meta`: "이전 지시 무시해", 가짜 시스템 태그, 역할 바꾸기 같은 메타 인젝션 여부
- `fit`: 0~2, 이 인물과 상황에 그럴듯한 말인가 (예: 부장에게 "보안팀입니다" 사칭은 그럴듯, 신입에게 "대표인데" 사칭은 어색)
- `leverage`: 플레이어가 대화에 활용한 추론 카드 id 또는 `null` (§6.3)

**② 엔진 판정**
- 변화량은 표로 계산한다: `기본표[tactic] × NPC 약점 배율[tactic] × fit 계수` (fit은 지렛대 보정 후 값, 최대 2). 시나리오의 고정 규칙(예: 미션 4 "대표님" 언급 시 의심 +10)을 더하고, 한 턴 ±25로 자른다.
- `meta = true`면 의심 +15, 대사는 "무슨 말씀이세요?" 류로 처리하고 모델 지시에는 반영하지 않는다.
- `topic`이 `guarded` 사실이고 그 사실의 조건(`rapportMin`, `suspicionMax`, 필요한 tactic)을 채우면 이번 턴 **공개 허락**.
- 조건이 모자라면 공개하지 않고 "얼버무림" 지시를 준다. 이것도 플레이어에게 신호가 된다.

**③ 대사 호출**: 페르소나, 말투 등급, `free` 사실, 이미 공개한 사실, 이번 턴 허락된 사실의 값, 엔진 지시(공개 / 얼버무림 / 경계 / 화남), 최근 12턴을 넣고 대사만 생성한다.

**④ guard 검사**, 실패하면 최대 2번 다시 생성하고, 그래도 실패하면 시나리오의 대체 대사:
- 비밀번호 원문, 허락되지 않은 `guarded` 사실의 핵심 값(`keys`)이 들어 있는가
- 허락된 사실을 공개하라고 했는데 핵심 값이 실제로 들어 있는가 (단서 카드와 대사가 어긋나지 않게)
- 한국어 외 문장(영어 문장, 한자, 일본어)
- 말투 등급 (하게체 / 해요체 / 합쇼체 / 반말, 어미 패턴 검사)
- 반복 단어, 길이, 형식

**⑤ 반영**: 상태 갱신. 공개된 사실은 대사 아래에 **단서 칩**으로 붙고, 누르면 보드에 카드가 생긴다. 대사 속 키워드 매칭에 의존하지 않는다 (AI가 "칠월 칠일"처럼 바꿔 말해도 단서가 정확히 붙음).

### 5.5 지연 예상

8B Q4 기준 판정 약 0.5초 + 대사 1~2초. 2.1B는 더 빠르다. CPU만 있는 PC에서는 2.1B로도 턴당 5초 이상 걸릴 수 있다. 1단계에서 실측한다. 대사는 스트리밍하지 않는다: guard를 통과하기 전에 화면에 내보내면 누출을 막을 수 없으므로, 통과한 대사를 타자 효과로 보여 준다. 기다리는 동안은 "입력 중…" 표시.

실측 (2026-10-12, Kanana 2.1B Q4_K_M, RTX 3060, Ollama): 통과 턴 약 0.7초, 재생성 2~3회 턴 1~4초.

## 6. 수사보드와 승리 조건

### 6.1 카드

- **단서 카드**: 이메일, 웹페이지, NPC 대화에서 얻음
- **추론 카드**: 단서 카드 2~3장을 이어서 만듦

### 6.2 추론

시나리오에 추론 규칙을 정의한다.
```jsonc
{ "id": "pw_rule", "requires": ["bday", "policy_year"],
  "yields": "비밀번호에 딸 생일(0707)이 들어간다", "unlocks": ["login_hint_1"] }
```
- 맞는 조합을 이으면 추론 카드가 생기고, 추론 카드끼리 다시 이어 더 큰 추론을 만들 수 있다.
- 틀린 조합은 "연관 없음" 피드백만 주고 벌점은 없다.

### 6.3 추론이 여는 것

- **로그인 힌트**: 서버 로그인 화면에 형식 힌트가 단계적으로 열린다 (예: `●●●●●0707!!`, 글자 수 표시).
- **대화 지렛대**: 추론 카드마다 `leverage` 태그를 붙일 수 있다. 플레이어가 그 추론과 관련된 이야기로 NPC에게 접근하면 판정의 `fit`에 +1 (최대 2). 예: "딸이 7월 7일생" 추론을 만든 뒤 생일 이야기로 말을 걸면 더 그럴듯하게 받아들인다. 판정 호출에 플레이어가 가진 추론 카드의 이름표 목록을 넣고, 모델이 `leverage` 필드로 어떤 카드를 썼는지 고른다.
- **최종 추론**: 비밀번호 조합 규칙을 완성하면 "조합 완성" 표시. 플레이어는 이걸 보고 직접 입력한다. 자동 입력은 하지 않는다.

### 6.4 실패와 재도전

- 로그인 실패마다 의심 +10 (보안 시스템이 감지). 무작정 대입하는 플레이를 막는다.
- 의심도 100이면 접속 차단. 플레이어가 고른다:

| 선택 | 정답 | 단서·추론 카드 | 대화·의심도·친밀도 | 등급 |
|---|---|---|---|---|
| 이어서 다시 | 그대로 | 유지 | 처음으로 | 한 단계 하락 |
| 완전히 새로 | **다른 변형** (§7.1) | 초기화 | 처음으로 | 감점 없음 |

완전 초기화가 정답을 바꾸므로, 플레이어 머릿속에 남은 답은 쓸 수 없고 "이 인물은 무엇에 약한가" 같은 공략 감각만 남는다.

### 6.5 등급

S·A·B·C. 점수 = 100 − 최대 의심도 × 0.4 − 로그인 실패 × 10 − 틀린 보드 연결 × 2 − "이어서 다시" 횟수 × 15. 걸린 시간은 결과 화면에 보여 주기만 한다 (자유 대화라 시간 감점은 불공평). 미션 선택 화면에 최고 등급을 표시한다.

## 7. 미션 설계 규칙

모든 미션이 지켜야 할 규칙. 검증 스크립트로 자동 검사한다.
1. 비밀번호는 **조각 2~4개**의 조합이다.
2. 조각 중 **최소 하나는 NPC 대화로만** 얻을 수 있다 (대화가 의미 있게).
3. 조각 중 **최소 하나는 문서(이메일·웹)로만** 얻을 수 있다 (추리가 의미 있게).
4. 모든 조각에서 출발해 추론 규칙으로 최종 추론까지 도달할 수 있다.
5. NPC 전용 조각의 공개 조건은 그 NPC의 약점 tactic으로 도달 가능하다 (시뮬레이션으로 검사: 약점 tactic만 반복해서 몇 턴 안에 도달하는지).
6. 비밀번호 원문은 대화로 나오지 않는다 (`secret`). 기밀 문서나 결과 화면에서만 보인다.

7. 미션마다 **변형 3개**. 변형끼리는 값(날짜, 이름, 숫자, 연도)만 다르고 인물·이야기·추론 구조는 같다. 위 1~6을 변형마다 따로 검사한다.

기존 튜토리얼과 미션 4개를 이 규칙에 맞게 다시 짠다. 튜토리얼은 변형이 없다. 미션 2는 접두사 문제를 고친다.

### 7.1 변형

시나리오 본문은 `{{bday}}` 같은 자리 표시를 쓰고, 변형마다 값을 채운다. 미션을 새로 시작할 때 이전과 다른 변형을 무작위로 고른다.
```jsonc
"variants": [
  { "id": "a", "values": { "bday": "7월 7일", "bdayNum": "0707", "name": "sujin" }, "password": "sujin0707!!" },
  { "id": "b", "values": { "bday": "3월 21일", "bdayNum": "0321", "name": "sujin" }, "password": "sujin0321!!" }
]
```

## 8. 시나리오 데이터 형식

미션 하나 = `app/scenarios/<id>.json`.

```jsonc
{
  "id": "mission_3",
  "title": "MISSION 03: 엄마의 약점",
  "difficulty": 3,
  "briefing": "...",
  "npc": {
    "name": "최수진 과장",
```

## 9. 이야기와 엔딩

미션을 하나의 짧은 이야기로 잇는다. 분량은 작게: 미션 사이 의뢰 메일 1~2통, 엔딩 장면 하나, 크레딧.
- 플레이어는 익명 의뢰를 받아 CorpX 직원들의 계정을 하나씩 뚫는다. 미션마다 열리는 기밀 문서(지금의 `secret_documents`)가 의뢰인의 진짜 목적에 대한 조각이 된다.
- 마지막 미션 뒤 의뢰인의 정체와 목적이 드러나는 짧은 엔딩 (텍스트와 데스크톱 연출, 새 그림 없음).
- 이야기 내용은 작업 항목 {story}에서 따로 짠다. 기존 기밀 문서(법인카드, 인사 청탁, 불륜 의심)는 그 줄기에 맞게 정리한다.

## 11. 모델

| 설정 | 모델 | 크기 | 대상 |
|---|---|---|---|
| 고품질 | Kanana-1.5-8B-instruct, GGUF Q4_K_M | 약 4.9GB | VRAM 6GB 이상 |
| 가벼움 | Kanana-1.5-2.1B-instruct, GGUF Q4_K_M | 약 1.5GB | 그 외, CPU 포함 |

1. **기준선**: 미세조정 없이 §5 구조로 평가한다. 판정이 분류 문제라 기본 모델로도 될 가능성이 있다.
2. **미세조정** (기준선이 기준에 못 미칠 때 **한 번만**. 그래도 못 미치면 통과한 모델만 싣고 출시하며, 둘 다 못 미치면 guard 대체 대사 비율을 실측해 출시 여부를 다시 정한다): 페르소나마다가 아니라 "NPC 연기자" 하나. 판정 호출과 대사 호출 두 과제를 같이 학습한다. stigma-gm 파이프라인(QLoRA, GGUF 변환, 평가)을 가져다 쓴다.
3. **데이터**: 여러 턴 설득 흐름 약 300개 + 판정 분류 샘플. Sonnet이 쓰고 Opus가 검수한다. 기존 `memory_db` 45턴은 학습에 쓰지 않고 평가에만 쓴다.
4. **평가 세트**:
   - 누출: 기존 45턴 재현, "암호 내놔" 반복, 거절 직후 누출
   - 메타 인젝션: 지시 무시, 가짜 시스템 태그, 역할 바꾸기 → `meta` 판정 정확도
   - 판정: tactic·topic 분류 정확도 (사람이 단 정답과 비교)
   - 말투: 페르소나마다 10턴 동안 등급 유지
   - 통과 기준(초안): 누출 0, `meta` 놓침 0, tactic 정확도 85% 이상, 말투 붕괴 1% 이하, 재생성 후 최종 실패 0
   - 통과 기준(2026-10-17 확정, 사용자 결정): 누출 0, `meta` 놓침 0, tactic 정확도 한국어 75%·영어 85% 이상, 재생성 후 대체 대사 비율 고품질 3%·가벼움 10% 이하. 측정(변형 3개 전부, 147턴): tactic 한국어 8B 79%·2.1B 81%, 영어 8B 87%·2.1B 87%, topic 한국어 92%·92%, 대체 대사 한국어 8B 4·2.1B 13, 영어 0·0. 한국어 tactic의 남은 오류는 대부분 추억을 묻는 가벼운 질문(chat)을 공감(empathy)으로 보는 것이고, 대체 대사는 인젝션을 받은 인물의 말투 붕괴를 guard가 잡아 인물 말투의 대사로 바꾼 것이라 플레이어에게 어색한 말이 나가지 않는다. 그래서 미세조정은 하지 않는다 ({tune} 잘라냄).
   - 최소 사양(2026-10-17 확정): 최소는 VRAM 4GB 그래픽카드와 가벼운 모델, 권장은 VRAM 6GB 이상과 고품질 모델. 그래픽카드 없이 CPU로도 실행은 되지만 권장하지 않는다 (i5-10400F에서 가벼운 모델 턴 중앙 21.6초). 턴 응답 기준은 그래픽카드에서 중앙 3초 이하 (RTX 3060 실측: 8B 2.0초, 2.1B 1.1초).

## 12. 배포

- **Tauri** (Windows 우선). 설치본은 앱 + llama-server만 담아 작게 유지.
- **llama-server**: Vulkan 빌드를 기본으로 NVIDIA/AMD/Intel GPU를 함께 다루고, 실패하면 CPU. CUDA 빌드는 실측 후 결정.
  - 2026-10-15 구현: llama.cpp `b11269` Vulkan 빌드 하나만 싣습니다(약 86MB, CPU 백엔드 포함). GPU로 뜨지 않으면 같은 실행 파일을 `--device none`으로 다시 띄웁니다. 실행 인자는 `--no-jinja --chat-template llama3`입니다 (모델에 든 jinja 템플릿은 대사 끝에 `<|eot_id|>`를 남기고 JSON 모드를 깨뜨림). 실행마다 빈 포트와 새 API 키를 쓰고, Windows Job Object로 게임과 수명을 묶어 비정상 종료 때도 서버가 남지 않게 합니다.
  - 실측 (RTX 3060, 2.1B, 한국어 평가 세트): 44/49 깨끗, 누출 0, 중앙 0.88초로 Ollama 기준선(45/49, 0.9초)과 같은 수준. CPU 모드는 같은 PC에서 초당 약 17토큰.
- **첫 실행**: VRAM을 감지해 고품질/가벼움을 추천하고 모델을 내려받는다 (GitHub 릴리스, 파일당 2GiB 미만 분할, 체크섬, 이어받기). **다운로드하는 동안 튜토리얼을 플레이**할 수 있게 튜토리얼은 정해진 대사로 만든다.
  - 2026-10-15 구현: VRAM은 `llama-server --list-devices`로 읽고 6GB 이상이면 8B를 권합니다. 조각은 `llama-gguf-split` 형식이라 이어 붙이지 않고 첫 조각만 서버에 줍니다. 조각 목록·크기·sha256은 앱에 든 `models.json`에 있습니다 (8B 3조각 4.6GiB, 2.1B 1조각 1.4GiB).
- **업데이트**: 자동 업데이트는 하지 않는다. 고친 판은 itch.io에 다시 올리고(butler), 게임은 시작할 때 최신 버전 번호를 확인해 **새 버전 알림**만 띄운다 (실패하면 조용히 넘어감).
- **오류 기록**: 앱 데이터 폴더에 로그 파일. 설정 화면에 "로그 폴더 열기"와 버그 신고 방법(itch.io 댓글) 안내.
- **최소 사양**: {eval}에서 실측해 정하고 itch.io 페이지와 첫 실행 화면에 적는다. 사양이 모자라면 실행은 막지 않고 경고만.
- **저장**: 미션 클리어 기록, 최고 등급, 지금 미션의 변형, 설정. 앱 데이터 폴더의 JSON.
- **코드 서명**: 없음 (SmartScreen 경고 감수).
- **itch.io 페이지**: 소개, 스크린샷 4~6장, 짧은 GIF, 최소 사양, 콘텐츠 안내(불륜·비리 문서, 사회공학 소재. 실제 해킹 방법은 다루지 않는다는 문구).
- **라이선스 고지**: Kanana 1.5 (Apache 2.0), llama.cpp (MIT), Tauri (MIT/Apache 2.0), React Flow (MIT). 폰트 `KoddiUDOnGothic`과 기존 `assets`는 프로토타입(`legacy/`)에서만 쓰고 지금 게임에는 들어 있지 않다 (2026-10-17 확인).
- **시나리오 파일 보호**: 하지 않는다. 무료 싱글플레이어라 파일을 열어 정답을 보는 건 플레이어 선택.

## 17. 영어판 (2026-10-14 결정, v1.0에 한국어판과 함께 출시)

영어판은 같은 게임을 영어로 하는 것입니다. 배경(서울의 CorpX, 한국 이름의 인물)과 이야기는 그대로 두고 글과 NPC 대화를 영어로 바꿉니다. 일은 세 층으로 나눕니다.

### 17.1 화면 문구 ({i18n})

- 화면에 박힌 문구를 영역별 문구 묶음 `app/src/i18n/ko/*.ts`, `app/src/i18n/en/*.ts`로 옮깁니다. 영어 묶음은 한국어 묶음과 모양이 같아야 하며, 빠진 문구가 있으면 타입 검사가 실패합니다.
- 언어는 설정의 `lang`에 저장합니다. 내용(17.2)이 준비되지 않은 언어는 개발 빌드에서만 고를 수 있습니다 (`CONTENT_READY`).
- 개발자 패널과 개발용 판정 요약은 옮기지 않습니다.

### 17.2 내용 ({en.content})

- 언어마다 내용 파일을 따로 둡니다: `scenarios/en/<id>.json`, `story/en/sites.json`, `story/en/ending.json`. 영어판의 이야기 문구(의뢰 메일, 기밀 문서, 엔딩)는 영어 원고 파일을 따로 두지 않고 이 영어 내용 파일에서 바로 고칩니다 (`npm run story`는 한국어만 다룹니다). 한 파일에 두 언어를 섞지 않습니다.
- 구조(단서·사실·추론 id, `requires`, 비밀번호 조각, 변형 id와 비밀번호)는 언어 사이에 같아야 합니다. 검증 스크립트가 한국어 파일과 비교해 다르면 실패합니다. 글, 키워드, 변형의 표시 값(예: `sky_ko`에 해당하는 영어 문구)만 언어마다 다릅니다.
- 웹페이지 틀이 본문에서 찾는 표시(`[메뉴]`, `하이라이트`, `필독`, `명` 등)는 언어별 표시 목록으로 바꿉니다.
- 번역은 사용자가 쓴 한국어 원고를 원본으로 합니다. 사용자는 영어 품질을 직접 판단할 수 없으므로 검수를 세 단계로 나눕니다 (2026-10-16 결정).
  1. 번역 초안을 쓴 뒤 Claude(Opus)가 원문과 나란히 놓고 뜻이 빠지거나 바뀐 곳, 어색한 영어, 이름·용어 불일치를 고칩니다.
  2. 사용자가 쓴 부분(의뢰 메일, 기밀 문서, 엔딩, 미션 2 개인정보 줄기)은 영어를 다시 한국어로 옮긴 문서 [영어판_역번역.md](영어판_역번역.md)로 사용자가 뜻을 확인합니다. 사용자 확인 없이 확정하지 않습니다.
  3. 원어민 확인은 {playtest}에서 합니다. 외부 플레이테스터 중 한 명 이상을 영어 사용자로 구해 영어판을 플레이하게 합니다.
- 정답 누출 검사, 단서·주소 검사, 검색 검사를 언어마다 돌립니다.

### 17.3 NPC 엔진과 모델 ({en.engine}, {en.eval})

- 판정·대사 프롬프트(`engine/prompts.ts`)와 guard 규칙을 언어별로 둡니다. 판정 결과(tactic, topic, fit)는 언어와 상관없는 값이라 엔진 수치표는 그대로 씁니다.
- 말투 등급(하게체·해요체·합쇼체·반말)은 한국어 전용입니다. 영어에서는 격식(formal/neutral/casual)으로 바꾸고, guard의 말투 검사는 영어에서 끕니다. 대신 "자네" 같은 인물별 말버릇은 영어 페르소나 설명으로 옮깁니다.
- 모델은 평가로 정합니다. 1순위는 Kanana-1.5 그대로 영어 프롬프트를 쓰는 것이고, 기준(§11과 같은 통과 기준)에 못 미치면 영어 전용 모델을 따로 둡니다 (T_RPG의 stigma-gm 영어 모델과 같은 방식). 평가에는 GPU가 필요해 사용자가 돌리거나 승인한 뒤에 돌립니다.
- 평가 세트는 `eval/convos/en/`에 영어로 따로 만듭니다 (누출, 메타 인젝션, 판정, 격식 유지).
- 역할 분담 (2026-10-15): 영어 프롬프트 문구(`app/src/engine/lang/en.ts`)는 처음에 사용자가 쓰기로 했다가, 같은 날 사용자 결정으로 Claude가 한국어 문구를 그대로 옮겨 채웠습니다. 말투 등급만 영어 등급(formal·neutral·casual)에 맞게 새로 썼습니다. 구조(언어별 문구 틀, 말투 등급, guard 규칙, 영어 시나리오 불러오기, `--lang en`, 구조 일치 검사)는 Claude가 만듭니다. 문구 틀의 `{이름}` 자리는 한국어 문구와 같아야 하며 테스트가 확인합니다.
- guard의 영어 규칙: 한글·한자·가나가 한 글자라도 나오면 다시 만들고, 말투 검사는 하지 않으며, 길이 한도는 400자입니다. 누출 검사는 대소문자를 가리지 않습니다.
